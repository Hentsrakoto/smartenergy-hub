# Étape 5 — reprise propre de Cassandra (2026-10-26)

## Diagnostic

`docker context show` renvoyait `desktop-linux`, où aucun conteneur Cassandra n'existait. `docker context ls` révélait aussi `default`, dont le daemon contenait l'ancien `cassandra` (`cassandra:4.0`, version interne 4.0.21), arrêté depuis quatre jours. Son volume anonyme contenait le keyspace `smartenergy` et d'autres projets. Une tentative de `docker --context default start cassandra` s'est terminée par le code de sortie 255 environ une minute plus tard, sans nouveaux logs applicatifs. La cause précise de ce code 255 n'a pas été établie.

La demande de reprise propre a été réalisée avec une nouvelle instance isolée. L'ancien conteneur et son volume ont été préservés ; aucune commande de suppression ni `DROP` CQL n'a été exécutée.

## Installation effectuée

L'image `cassandra:4.0` était déjà présente dans le contexte `default` et annonce `CASSANDRA_VERSION=4.0.21`. La machine disposait d'environ 1,9 Gio de mémoire disponible lors de l'inspection. La nouvelle instance utilise un heap de 512 Mio, un volume nommé dédié et un port CQL accessible seulement depuis l'hôte :

```bash
docker --context default run -d --name smartenergy-cassandra \
  --mount type=volume,source=smartenergy_cassandra_data,target=/var/lib/cassandra \
  -p 127.0.0.1:9042:9042 \
  -e MAX_HEAP_SIZE=512M -e HEAP_NEWSIZE=100M cassandra:4.0
```

**Commande déjà exécutée : ne pas la répéter tant que le conteneur existe.** Vérification exécutée :

```bash
docker --context default exec smartenergy-cassandra nodetool status
```

Résultat : nœud `UN` à `172.17.0.2`. `docker inspect` confirme `status=running`, `smartenergy_cassandra_data:/var/lib/cassandra` et `127.0.0.1:9042->9042`.

## Schéma, requête et tests

```bash
docker --context default exec -i smartenergy-cassandra cqlsh < scripts/init_cassandra.cql
docker --context default exec smartenergy-cassandra cqlsh -e \
  'DESCRIBE TABLE smartenergy.measurements_by_sensor_day;'
```

Les deux commandes ont réussi. La table a la clé primaire `((sensor_id, day), measured_at)` et le clustering `measured_at DESC`. Le keyspace et la table sont créés avec `IF NOT EXISTS`. La partition `(sensor_id, day)` correspond aux lectures par capteur et jour, et limite la taille d'une partition à une journée.

Écriture puis lecture réellement exécutées :

```bash
docker --context default exec smartenergy-cassandra cqlsh -e \
  "INSERT INTO smartenergy.measurements_by_sensor_day (sensor_id, day, measured_at, power_kw, voltage, temperature) VALUES ('stage5-check-20261026', '2026-10-26', '2026-10-26T12:00:00Z', 4.25, 230.0, 22.5);"
docker --context default exec smartenergy-cassandra cqlsh -e \
  "SELECT sensor_id, day, measured_at, power_kw, voltage, temperature FROM smartenergy.measurements_by_sensor_day WHERE sensor_id='stage5-check-20261026' AND day='2026-10-26';"
```

Résultat : une ligne, `2026-10-26 12:00:00+0000`, `4.25 kW`, `230 V`, `22.5 °C`.

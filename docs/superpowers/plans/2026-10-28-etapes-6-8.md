# Étapes 6 et 8 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox syntax for tracking.

**Goal:** Compléter les rapports MongoDB et les routes de consultation, puis prouver leur disponibilité dans Swagger UI.

**Architecture:** Les rapports et l'index des jours proviennent des agrégats MongoDB existants. Les mesures restent dans Cassandra ; les calculs de plage utilisent les seuils du capteur MongoDB. Les deux services Spring restent sur l'hôte.

**Tech Stack:** Java 17, Spring Boot 3.3.4, Spring Data MongoDB/Cassandra, JUnit 5, springdoc OpenAPI compatible.

**Spec:** `docs/superpowers/specs/2026-10-28-etapes-6-8-design.md`

## Global Constraints

- Pas de suppression de données, `DROP`, ni changement des ports ou volumes Docker.
- Préserver les contrats HTTP existants ; validation des entrées et erreurs compréhensibles.
- Les étapes 6 et 8 demeurent « En cours » sans preuve d'intégration et validation étudiante.

## Review Focus

- Plage `from > to` : HTTP 400 homogène.
- Plage excessive : refuser avant les lectures Cassandra.
- Événement ancien arrivé après un récent : la dernière mesure reste la plus récente grâce au tri des jours d'agrégat.
- Rapport présent dans MongoDB : lecture sans Cassandra.
- Dépassement exact de seuil : pas une anomalie si la règle est strictement `>`.
